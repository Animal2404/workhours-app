记账体验大更新：批量记账 + 累计收入/逐月明细 + 存款目标（附一个存在已久的进度环 bug）

用户用下来提了三件事，逐条做掉，另外补了两处。

1. 批量记账（原来只能一天一天记）
   - 日历右上角新增批量模式开关；进入后点格子 = 勾选
   - 快捷选中：整月 / 本月已过 / 清空选择
   - 底部操作条显示「已选 N 天」，一次给这些天记同样的班
   - 新增 BatchSheet：班次模板、工时、加班、时薪、补贴扣款、备注，带合计预览
   - 走 store 的 upsertMany / removeMany：**一次 dispatch、一次落盘**
     （不是循环调 upsert —— 选 31 天那样会跑 31 次 reducer + 31 次写盘）
   - 已有记录会明确提示「保存后会覆盖」；记完自动退出批量模式

2. 所有月工资总和（原来只显示当月）
   - 日历顶部卡片在「本月已赚」下新增一行：**累计**（所有月份）+ **环比上月**
   - 统计页新增「全部」档：全部记录汇总 + **逐月明细**（从新到旧，点一行跳到那个月）
   - pay.ts 新增 summarizeAll / monthlyHistory / monthOverMonth

3. 存款目标（攒钱买东西）
   - 目标页新增「存款目标」区块：可加多个目标
   - 新增 GoalSheet：名字（含「换手机/买电脑/去旅游…」快捷）、目标金额、
     起算日（今天 / 本月 1 号 / 今年开始 / 全部记录）、已存
   - 每张卡显示：环形进度 %、已攒、还差、**还要上几天班**、**预计达成日期**、出勤与日均
   - 口径写在代码注释里：天数按「每个出勤日平均收入」推（是出勤日），
     预计达成日按「每个自然日平均收入」推（会把休息日算进去），两者不同是有意的
   - 起算日决定哪些收入算进来；起算日在未来则一分钱都不计入（不夹到今天）

4. 补：修好「进度环的彩色弧从来没画出来」
   排查存款目标截图时发现弧线不显示，查下来是**存在已久**的 bug：
   CSS 里写死 `.ring-bar { stroke: url(#ringGrad) }`，而组件用 useId() 给每个环
   生成唯一渐变 id 写在 SVG **行内属性**上；CSS 优先级高于 presentation attribute，
   于是行内正确的 url(#r0) 被盖成文档里不存在的 url(#ringGrad) → 弧线整条不渲染。
   实测 computedStroke=url("#ringGrad") 且 getElementById('ringGrad')=null。
   删掉 CSS 里那行 stroke 即可（颜色交给组件行内属性）。
   影响面：**月度目标环与新增的存款目标环都受影响**，之前一直只有灰底环。

5. 补：「记账提醒」从空壳变成真的会提醒
   原来 reminderEnabled/reminderTime 只有开关和一行 sr-only 文案，**没有任何逻辑**。
   现在：开了开关、过了设定时间、今天还没记录 → 打开 App 时顶部提醒一句，可「去记」或当天不再提醒。
   明确是**应用内提醒**不是系统推送（WebView 没有原生通知能力，要做需引入 Capacitor 插件改原生），README 里写清楚了。
